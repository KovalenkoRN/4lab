# Лабораторная работа 4 «Калькулятор скидок» (React + Vite)

Калькулятор принимает цены товаров и их категории, считает скидку, цену после скидки, НДС 22 % и итоговую сумму к оплате, показывает промежуточные вычисления.
Основной компонент — `src/DiscountCalculator.jsx`, стили — `src/DiscountCalculator.css`.

## Запуск

Нужен Node.js 18 или новее.

```
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

## Категории и формулы

| Категория | Скидка |
|---|---|
| Электроника | 5 % |
| Одежда | 15 % |
| Продукты | 10 % |
| Книги | 20 % |
| Другое | 0 % |

```
discountAmount     = price × (discountPercent / 100)
priceAfterDiscount = price − discountAmount
vatAmount          = priceAfterDiscount × 0.22   // НДС начисляется после скидки
total              = priceAfterDiscount + vatAmount
```

## Самостоятельная работа

1. **Несколько товаров.** Товары хранятся массивом в `useState` (`items`), у каждого своя цена, категория и ошибка валидации. Товары можно добавлять кнопкой «+ Добавить товар» и удалять (✕). В результате — таблица по каждой позиции и итог как сумма по всем позициям. Все цены проверяются при нажатии «Рассчитать».
2. **Промокод.** Поле «Промокод»: при вводе `WELCOME10` (регистр не важен) добавляется ещё 10 % скидки поверх категорийной — от цены, уже уменьшенной на скидку категории. Под полем выводится «Промокод применён» или «Такого промокода нет».
3. **Кастомная скидка.** Переключатель «Своя скидка вместо скидки категории» показывает ползунок (`range` от 0 до 50 %). Пока он включён, выбранный процент заменяет скидку категории для всех товаров, а выбор категорий блокируется.
4. **Переключатель НДС.** Флаг `withVat` в `useState` управляет тем, прибавляется ли НДС 22 % к итогу. Без НДС в строке налога пишется «не начисляется».
5. **История расчётов.** Каждый успешный расчёт добавляется в массив `history` (время, количество товаров, тип скидки, промокод, НДС, итог). Под формой выводятся последние 5 расчётов, новые сверху; историю можно очистить. «Сбросить» очищает форму, но не историю.

## Ответы на контрольные вопросы

**1. Почему цена хранится в состоянии как строка, а не как число?**
Поле ввода в React работает со строками: `value` всегда строка. Если хранить число, промежуточные значения ломаются: пустое поле превратится в `NaN` (`parseFloat("")`), а ввод `"10."` — в `10`, и точка исчезнет, так что дробь не набрать. В строке можно хранить любое промежуточное состояние ввода, а в число её переводить только при расчёте.

**2. Зачем нужен флаг `calculated` и что изменится, если его убрать?**
Он отделяет ввод от результата: результаты показываются только после нажатия «Рассчитать» и только для проверенных данных. Без флага таблица результатов была бы видна сразу и менялась при каждом символе, в том числе с неверными или незаконченными данными (например, `0` или пустая цена), а кнопка «Рассчитать» и валидация потеряли бы смысл.

**3. Почему при каждом `onChange` сбрасывается `calculated` в `false`?**
После изменения цены, категории (или промокода, скидки, НДС) старый результат уже не соответствует введённым данным. Сброс скрывает устаревший расчёт, чтобы пользователь не принял его за актуальный, и требует снова нажать «Рассчитать» — тогда данные заново пройдут проверку.

**4. Как работает регулярное выражение `/^\d*\.?\d*$/` в `handlePriceChange`?**
`^` и `$` — начало и конец строки, то есть проверяется вся строка целиком. `\d*` — ноль или больше цифр, `\.?` — необязательная одна точка, `\d*` — снова ноль или больше цифр. Подходят `""`, `"12"`, `"12."`, `"12.5"`, `".5"`; не подходят буквы, минус, пробелы и вторая точка. Если новое значение не совпадает с шаблоном, состояние не обновляется — лишний символ просто не появляется в поле.

**5. В чём разница между `onClick` и `onChange` для кнопки и поля ввода?**
`onClick` срабатывает при нажатии на элемент — для кнопки это действие пользователя («Рассчитать», «Сбросить»), данных оно не несёт. `onChange` срабатывает при изменении значения поля (каждый введённый или удалённый символ, выбор пункта в списке, перемещение ползунка, переключение флажка) и передаёт новое значение в `e.target.value` / `e.target.checked`, которое мы записываем в состояние.
